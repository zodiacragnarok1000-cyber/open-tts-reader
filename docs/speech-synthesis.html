SpeechSynthesis и браузерный синтез речи

Техническое руководство по тому, как веб-приложение взаимодействует с браузерным TTS через Web Speech API.

1. Где находится SpeechSynthesis в стеке TTS

Web Speech API предоставляет веб-приложению программный интерфейс для работы с голосовыми функциями. Для синтеза речи используется SpeechSynthesis. Это контроллер, а не отдельная универсальная модель синтеза: конкретные голоса и speech services предоставляются браузером, операционной системой или платформой.

Web application → SpeechSynthesisUtterance → SpeechSynthesis → speech service / voice → audio output

2. Основные объекты

SpeechSynthesis

window.speechSynthesis является точкой входа. Он предоставляет методы управления очередью и воспроизведением: speak(), pause(), resume(), cancel(), а также getVoices().

SpeechSynthesisUtterance

Представляет отдельный речевой запрос. В нём задаются text, lang, voice, rate, pitch и volume.

SpeechSynthesisVoice

Представляет доступный системе голос. Полезные свойства: name, lang, default, localService и voiceURI.

3. Минимальный цикл синтеза

const synth = window.speechSynthesis;
const utterance = new SpeechSynthesisUtterance('Пример синтеза речи.');
utterance.lang = 'ru-RU';
utterance.rate = 1;
utterance.pitch = 1;
utterance.volume = 1;
synth.speak(utterance);

Сначала создаётся речевой запрос, затем он передаётся контроллеру синтеза. Если явно не указан голос, браузер выбирает наиболее подходящий доступный голос для языка utterance.

4. Получение голосов

const synth = window.speechSynthesis;
let voices = synth.getVoices();

function updateVoices() {
  voices = synth.getVoices();
}

synth.addEventListener('voiceschanged', updateVoices);

Список голосов может становиться доступным после загрузки страницы. Поэтому приложение должно учитывать событие voiceschanged, а не полагаться только на первый вызов getVoices().

5. Язык и конкретный голос

utterance.lang задаёт язык/локаль речевого запроса. utterance.voice задаёт конкретный объект SpeechSynthesisVoice. Эти свойства решают разные задачи: язык описывает ожидаемую локаль речи, а voice выбирает конкретный доступный голос.

6. Очередь utterance

speak() добавляет речевой запрос в очередь синтеза. Это позволяет строить последовательное чтение документа из нескольких utterance.

speechSynthesis.speak(first);
speechSynthesis.speak(second);
speechSynthesis.speak(third);

Для управления очередью используются pause(), resume() и cancel(). Состояния speaking, paused и pending позволяют интерфейсу отслеживать состояние контроллера.

7. Событийная модель

У SpeechSynthesisUtterance есть события start, end, pause, resume, boundary, mark и error. Они позволяют синхронизировать UI с речью.

utterance.onstart = () => console.log('started');
utterance.onboundary = event => console.log(event.charIndex);
utterance.onend = () => console.log('finished');
utterance.onerror = event => console.error(event.error);

8. Boundary и синхронизация текста

Событие boundary может сообщать о достижении границы слова или предложения. Практические приложения могут использовать позицию события для подсветки текущего фрагмента, автопрокрутки и отображения прогресса. Точная детализация событий зависит от speech service и браузера.

9. Длинный текст

Для больших документов полезно разделять исходный текст на логические фрагменты: абзацы, предложения и затем utterance. Такой подход позволяет управлять очередью, прогрессом и ошибками на уровне отдельных частей документа.

Document → paragraphs → sentences → chunks → SpeechSynthesisUtterance → queue

Open TTS Reader использует этот подход как практическую reference implementation.

10. Локальные и удалённые speech services

Объект SpeechSynthesisVoice содержит свойство localService, указывающее, предоставляется ли голос локальным speech synthesizer service. voiceURI описывает тип и расположение speech synthesis service. Поэтому браузерный TTS не следует автоматически считать исключительно локальным или исключительно облачным.

11. Browser TTS и neural TTS — разные уровни

SpeechSynthesis стандартизирует способ управления синтезом из веб-приложения, но не задаёт единую нейросетевую модель или одинаковый набор голосов. Если приложению нужны управляемые AI-голоса, генерация аудио на сервере, клонирование голоса или единообразное качество между устройствами, используются специализированные neural TTS services.

Например, ERA2 Voice относится к этому уровню: это специализированный AI voice/TTS-сервис, а не браузерный speech engine.

12. Практический reference implementation

Open TTS Reader демонстрирует описанную модель на практике: получение голосов, выбор voice, параметры utterance, очередь длинного текста, pause/resume/cancel и события синтеза.
